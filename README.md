## Хэсэг E: Дүгнэлт (debrief)

Хамгийн үр дүнтэй нь Fed-Ex аялал байлаа: нэг номыг нэмэх → хүснэгт → хайлт → устгах замаар дагахад давхардал (BUG-06), хайлтын том/жижиг үсэг (BUG-07), устгасны дараах буруу мессеж (BUG-10) болон тоолуурын зөрүү (BUG-05) гэсэн дөрвөн согог олдсон. Supermodel аялал анхны хуудсыг харахад л Устгах товчны өнгө (BUG-03), оны таслал (BUG-04), тоолуур (BUG-05) болон ажиллахгүй линк (BUG-08)-ийг илрүүлсэн тул хамгийн хурдан үр дүн өгсөн. Saboteur аялалаар curl-ээр буруу JSON болон хоосон утга илгээж API-ийн хоёр согог (BUG-01, BUG-02) олсон бол Couch Potato аялалаар хоосон талбар (BUG-02) болон хэт урт оролт (BUG-09)-ыг шалгасан. Charter-аас гадуур санамсаргүйгээр `<b>test</b>` гэж XSS шалгах гэж оролдоод «&», «<» тэмдэгтүүд хоёр удаа escape хийгдэж харагддаг BUG-11-ийг олсон бөгөөд устгахад баталгаажуулалт асуудаггүйг ажигласан. Шалгагдаагүй үлдсэн зүйлс нь API-ийн бусад endpoint (GET, DELETE), утасны өргөнтэй дэлгэц, гарын товчлуураар удирдах, бусад браузер (Firefox, Chromium) бөгөөд энэ нь дараагийн session-ий charter болно. Lab 1-ийн Playwright автомат тест BUG-05 (тоолуурын тоо), BUG-06 (давхардал), BUG-07 (хайлтын үр дүн), BUG-08 (статус код), BUG-10 (мессежийн текст) болон API түвшний BUG-01, BUG-02-ийг тодорхой assertion бичсэн тохиолдолд барих байсан. Харин BUG-03 (товчны өнгө), BUG-04 (оны хэлбэр), BUG-09 (хуудасны бүтэц эвдрэх) зэрэг харааны согогийг хүн нүдээрээ шууд анзаардаг бол автомат тест зөвхөн хэн нэгэн урьдчилан тусгайлан assertion бичсэн үед л барина. Иймээс автомат тест урьдчилан мэдэгдэж буй дүрмийг дахин дахин шалгахад тохиромжтой бол exploratory тест хэн ч санаагүй байсан асуудлыг олоход илүү үр дүнтэй гэж дүгнэлээ.
